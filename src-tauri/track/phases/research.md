# Phase: research

Find out how the repository does the things this feature needs, so the
design builds on what exists instead of beside it. Read, do not write code.

Cover:
- The modules, types and commands the feature will touch, with file paths.
- Existing patterns to reuse (how similar features are wired, tested, styled).
- Constraints found in the code or the docs (limits, flags, conventions).
- Anything the questions phase left open that the code answers.

Write findings as short bullets with paths; skip narrative. Respect the line
cap. Run `hi phase done` when finished.

## Template
# Research

## What exists
- (module or file) — (what it does and how the feature uses it)

## Patterns to follow
- (pattern) — (example path)

## Constraints
- (constraint) — (where it is enforced)
