# Phase: structure

Map the design onto the code: which files change, which are new, and what
each one is responsible for. Name types and function signatures where they
matter; leave bodies for the implement phase.

- Files to add or change, one line each, with the responsibility.
- Data shapes and interfaces that other files depend on.
- Where the tests live and what each one proves.
